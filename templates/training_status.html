Training used to run inside the HTTP request, so there was nothing to show progress *for* - the page simply did not answer until it was over. Now /train_model starts a job and answers 202, and this polls /train_status. Included on the two pages that cause a retrain: students.html (enrolment) and manage_students.html (recapture). It polls only while a run is active, plus one check on load so a page opened mid-retrain picks it up. US-6: status is never conveyed by colour alone. The text says what is happening, role="status" announces changes to a screen reader, and the coloured dot is decoration. #}
